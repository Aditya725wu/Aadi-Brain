

## title: AWS S3

# 🪣 AWS S3

> Amazon S3 (Simple Storage Service) is an object storage service used to store and retrieve data from anywhere over the internet.

# What is S3?

**S3 = Simple Storage Service**

Amazon S3 is an **object storage service** provided by AWS.

It is mainly used to store:

- Images
    
- Videos
    
- Documents
    
- PDFs
    
- Backups
    
- Logs
    
- Datasets
    
- Website files
    
- Application files
    

### Simple Example

Suppose I build a website where users upload profile pictures.

Instead of storing those images directly inside my server:

```text
User
  ↓
Website
  ↓
AWS S3
  ↓
Profile Image
```

S3 stores the image safely and makes it available when required.

# 🧠 S3 Basic Structure

S3 mainly works with:

```text
AWS Account
     ↓
   Bucket
     ↓
   Objects
     ↓
    Data
```

---

# 🪣 Bucket

A **Bucket** is a container used to store objects.

Think of a bucket like a folder/container in the cloud.

Example:

```text
my-aadi-project
│
├── images/
│   ├── profile.jpg
│   └── logo.png
│
├── documents/
│   └── resume.pdf
│
└── videos/
    └── demo.mp4
```

The bucket is:

```text
my-aadi-project
```

---

# 📦 Object

An **object** is the actual data stored inside an S3 bucket.

Examples:

```text
profile.jpg
resume.pdf
video.mp4
dataset.csv
```

An object generally consists of:

- Data
    
- Key
    
- Metadata
    

---

# 🔑 Object Key

The **key** identifies an object inside a bucket.

Example:

```text
images/profile.jpg
```

Here:

```text
images/profile.jpg
       ↑
      Key
```

S3 does not use traditional folders in the same way as a local file system. What looks like folders is generally represented through object key prefixes.

# 🌍 S3 Bucket Region

When creating a bucket, you choose an AWS Region.

Example:

```text
Bucket
   ↓
Asia Pacific (Mumbai)
ap-south-1
```

Choosing an appropriate region can help with:

- Latency
    
- Data residency requirements
    
- Cost
    
- Application architecture

# 🔒 Block Public Access

AWS provides **Block Public Access** settings to help prevent accidental public exposure of S3 data.

For private application data, public access should generally remain blocked unless there is a specific reason to expose the data.

---

# 🔐 Encryption

S3 supports encryption for stored objects.

Two broad approaches are:

```text
Server-Side Encryption
        ↓
AWS encrypts stored data
```

and

```text
Client-Side Encryption
        ↓
Application encrypts data before uploading
```

Common S3 server-side encryption options include:

- SSE-S3
    
- SSE-KMS
    
- SSE-C
    

---

# 🗂️ S3 Storage Classes

S3 provides different storage classes for different access patterns.

Common examples:

|Storage Class|Typical Use|
|---|---|
|S3 Standard|Frequently accessed data|
|S3 Intelligent-Tiering|Data with changing access patterns|
|S3 Standard-IA|Infrequently accessed data|
|S3 One Zone-IA|Infrequently accessed, reproducible data|
|S3 Glacier Instant Retrieval|Archive data needing quick retrieval|
|S3 Glacier Flexible Retrieval|Long-term archive|
|S3 Glacier Deep Archive|Very long-term archive|

---

# ♻️ Versioning

S3 Versioning allows multiple versions of an object to be retained.

Example:

```text
profile.jpg
    ↓
Version 1
    ↓
Version 2
    ↓
Version 3
```

If an object is accidentally overwritten or deleted, previous versions may be available depending on the bucket's configuration and lifecycle.

---

# 🔄 Lifecycle Rules

S3 Lifecycle rules can automatically manage objects.

Example:

```text
New Object
    ↓
S3 Standard
    ↓
After some time
    ↓
Infrequent Access
    ↓
Later
    ↓
Glacier
```

This can help manage storage costs and retention requirements.

# ☁️ S3 + EC2

S3 and EC2 have different purposes.

```text
EC2
 ↓
Compute
 ↓
Run application
```

```text
S3
 ↓
Storage
 ↓
Store files/data
```

They can work together:

```text
        Application
             ↓
           EC2
             ↓
           S3
             ↓
      Images / Files
```

# 🧑‍💻 AWS CLI

You can interact with S3 using the AWS CLI.

List buckets:

```bash
aws s3 ls
```

Copy a local file to S3:

```bash
aws s3 cp file.txt s3://my-bucket/
```

List objects:

```bash
aws s3 ls s3://my-bucket/
```

Download an object:

```bash
aws s3 cp s3://my-bucket/file.txt .
```

# 🏗️ Real-World Example

Suppose you build a student management application.

```text
Student
   ↓
Web Application
   ↓
Backend
   ↓
S3
   ↓

```

```text
student-documents/

├── certificates/
├── resumes/
└── documents/
```

The application can store the files in S3 while keeping the application's structured metadata in a database.

# 🧠 S3 vs EC2

|Feature|S3|EC2|
|---|---|---|
|Main purpose|Object storage|Compute|
|Stores files|✅|Possible, but not its primary purpose|
|Runs applications|❌|✅|
|Virtual machine|❌|✅|
|Scaling model|Managed object storage|Virtual server instances|

### Memory Trick

```text
EC2 → Computer 🖥️
S3  → Storage 🪣
```
